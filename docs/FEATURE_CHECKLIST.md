# 다이브 기능 점검표 (핵심 기능 3가지)

기준 커밋: `8ce5e84`(22단계). 점검일: 2026-10-27. 점검 PC: Windows, Node.js `v24.19.0`.
이 표는 코드를 고치지 않고 앱을 실행해서 화면을 읽은 결과입니다. 키·토큰·비밀번호는 없습니다.

## 값의 두 종류 (섞어 읽지 않기)

| 표시 | 뜻 |
|---|---|
| **[예시 화면 · 설명용 값]** | `npm run demo`의 예제 자료입니다. `연습 사용자`, `연습 PC`, `event-01` 같은 값은 실제 조회 결과가 아닙니다. |
| **[내 PC에서 잰 값]** | `npm start`로 실행해 실제로 확인한 값입니다. 지금은 회사 시스템(접근 제어·XDR)에 연결되지 않아 `engine.mode: disconnected`, `engine.code: ENGINE_NOT_CONNECTED`만 실제로 확인됩니다. |

## 기능 점검표 · 다듬을 순서: 기록 보기 → 내 PC 상태 → 위험 알림

| 순서 | 핵심 기능 | 화면 함수 | [예시 화면 · 설명용 값] (`npm run demo`) | [내 PC에서 잰 값] (`npm start`) | 지금 상태 |
|---|---|---|---|---|---|
| 1 | **기록 보기** (접속·XDR 목록, 필터, 상세) | `renderEvents` | 1건(`event-01`) 표시. 필터 세 개와 상세 열기 동작. 여러 건 정렬은 예시 자료가 1건뿐이라 이 화면에서는 못 봄 | 「기록을 불러오지 못했습니다」 + 연결 확인 불가 안내. 기록 0건과 구분되어 표시됨 | **화면은 됨 / 실제 기록은 아직 안 됨** |
| 2 | **내 PC 상태** (로그인 사용자·기기·세션) | `renderIdentity`, `renderStatus` | `연습 사용자`, `연습 PC`, 세션 `활성(active)`. 기기 상태는 `확인 불가(unknown)`라서 「보안 기준 충족/미충족」 화면은 예시로도 못 봄 | 사용자·기기·세션 모두 「연결 실패」 + 연결 확인 불가 안내 | **화면은 됨 / 실제 값은 아직 안 됨** |
| 3 | **위험 알림** (알림 목록, 조치 요청 상태) | `renderStatus`, `renderAction` | 알림 목록은 표시됨. 조치 제안이 없어 「조치 준비」 버튼이 나오지 않음 | 연결 없음. 조치는 시작할 수 없음 | **아직 안 됨** (이유: 접근 제어·XDR 연동과 조치 준비는 운영 측 연결이 필요) |

## 판단 근거와 한계

- 「지금 됨」은 **화면이 상태별로 올바르게 그려진다**는 뜻이지, 실제 회사 데이터가 나온다는 뜻이 아닙니다.
- 「연결 없음」을 「기록 없음」이나 「정상」으로 읽지 않습니다. 확인 불가는 정상이 아닙니다.
- 이 점검에서 실제 회사 시스템, 실제 AI 요청, 보안 조치는 실행하지 않았습니다.
- 확인하지 않은 것: 실제 연결(`connected`) 상태, 계정 연결 절차, 패키지 취약점 조회, 업무 앱 판정의 실제 연결 값.

## 같은 결과를 다시 만드는 방법

작업 폴더: `package.json`이 있는 앱 폴더(새로 만들지 않고 22단계까지 쓰던 이 폴더).

```powershell
cd <앱 폴더>
```

1. 예시 화면 확인

```powershell
npm run demo
```

브라우저에서 `http://127.0.0.1:5189`를 열고 아래를 확인합니다. 끝나면 실행한 창에서 `Ctrl+C`로 끕니다.
   - **기록 보기**: 보안 기록 메뉴에서 필터 세 개와 `event-01 상세`가 동작하는가
   - **내 PC 상태**: 보호 현황의 학생 칸에 사용자·기기·세션이 보이는가
   - **위험 알림**: 상태·알림 칸에 알림이 표시되고, 조치 칸에 「조치 준비」 버튼이 없는가

2. 내 PC에서 잰 값 확인

```powershell
npm start
```

같은 주소를 열어 세 기능이 「연결 실패/확인 불가」로 표시되는지 확인하고, 서버가 켜진 상태에서 아래를 실행합니다(새 PowerShell 창).

```powershell
curl http://127.0.0.1:5189/api/diagnostics
```

`engine.mode`가 `disconnected`, `engine.code`가 `ENGINE_NOT_CONNECTED`이면 위 표와 같은 결과입니다.

3. 문법 확인

```powershell
npm run check
```

실행이 안 되면 새 폴더를 만들지 말고, 오류 문구 전체를 복사해 AI에게 보여 주세요. 먼저 `PS` 프롬프트가 앱 폴더인지(`dir package.json`) 확인합니다.

### 읽는 방법(관리자 권한 필요 없음)
| 항목 | 방법 | 단위·범위 |
|---|---|---|
| CPU 사용률 | `os.cpus()` 누적 시간을 0.5초 간격으로 두 번 읽은 차이 | % (0.5초 평균) |
| 메모리 사용량 | `os.totalmem()` − `os.freemem()` | GiB와 % |
| 디스크 남은 공간 | `fs.statfs()` (앱 폴더가 있는 드라이브) | GiB. PC 전체가 아님 |

읽지 못하면 0이나 예시 값 대신 `확인 불가 · 이유: …`로 표시합니다. 버튼을 누를 때만 읽고 자동으로 반복하지 않습니다.

### 값 구분
- **[내 PC에서 잰 값]**(2026-10-31, 이 PC): 서버 응답 CPU 7.5%, 메모리 9.3 / 13.8 GiB(67.3%), 디스크 남음 38 / 237.4 GiB. 같은 시각 Windows 쪽 값(CPU 9.0%, 메모리 9.3 GiB, 디스크 38.0 GiB 남음)과 비교해 CPU만 몇 %p 차이, 나머지는 같았음.
- **[예시 화면 · 설명용 값]**: 이 기능에는 없습니다. `npm run demo`에서도 PC 값은 예시로 바꾸지 않고 실제로 잽니다. 안내 화면의 CPU·메모리 막대(14:02)는 설명용 예시이고 내 PC 값이 아닙니다.

CPU는 순간값이라 누를 때마다 크게 달라지고, 작업 관리자 값과 몇 %p 차이가 날 수 있습니다(측정 시점과 집계 범위가 다름).

### 다시 만드는 순서
1. 앱 폴더에서 `npm run check`
2. 서버가 켜져 있다면 끄고(`Ctrl+C`) `npm start` (서버 파일을 바꿨으므로 반드시 다시 켜기)
3. `http://127.0.0.1:5189`에서 「내 PC 상태(CPU·메모리·디스크)」 칸의 「PC 상태 다시 조회」를 두 번 누르기
4. 잰 시각, 단위, 이전 값과의 차이, 아래 최근 기록 줄이 늘어나는지 확인
5. 작업 관리자(성능 탭)를 같은 시각에 열어 CPU·메모리 사용량과 C: 남은 공간을 비교. 값이 다르면 측정 시점과 집계 범위(순간값 vs 평균)부터 확인
6. 서버 응답만 보고 싶으면 `curl http://127.0.0.1:5189/api/pc-status`

## 3일차: 연결 상태·방화벽 설정·Windows 기록 (읽기만)

### 제공 부분과 내가 바꾼 부분
| 구분 | 내용 |

### 읽는 방법(관리자 권한 필요 없음, 설정은 바꾸지 않음)
| 항목 | 읽기 전용 명령 | 화면 표시 |
|---|---|---|
| 네트워크 연결 | `Get-NetAdapter` | 어댑터 이름·유선/무선/가상·연결됨 여부. IP·MAC 주소는 표시하지 않음 |
| 방화벽 설정 | `Get-NetFirewallProfile` | Domain·Private·Public 켜짐/꺼짐, 「읽기만 함」 |
| Windows 경고·오류 | `Get-WinEvent`(System, Application, 최근 24시간) | 오류 N건·경고 N건, 「침해 판정 아님」 |
| SDP 서버 | 서버가 아는 실행 모드 | `SDP 미연결` / `예제 자료(SDP 연결 아님)` / `확인 불가`+이유. PC 조회 결과와 따로 표시 |

- 설정을 바꾸는 명령(`Set-`, `New-`, `Remove-`, `Enable-`, `Disable-`, `netsh ... set`)은 코드에 없습니다. 명령은 고정 문구이고 사용자 입력이 들어가지 않습니다.
- 읽지 못하면 0이나 예시 값 대신 `확인 불가 · 이유: …`로 표시합니다(권한 없음, 시간 초과 12초, PowerShell 없음, Windows 아님 등). 버튼을 누를 때만 읽고 자동 반복하지 않습니다.
- 경고·오류 건수는 시스템이 남긴 기록의 개수이며 침해나 공격을 탐지한 결과가 아닙니다.
- 읽는 데 약 7초 걸렸습니다(PowerShell 4개를 동시에 실행).

### 값 구분
- **[내 PC에서 잰 값]**(2026-10-31, 일반 권한): 네트워크 Wi-Fi 무선 연결됨과 가상 어댑터(vEthernet) 연결됨, 방화벽 3개 프로필 모두 켜짐, System 오류 14건·경고 19건, Application 오류 7건·경고 12건(최근 24시간), SDP 미연결.
- **[예시 화면 · 설명용 값]**: 안내 화면의 「유선 연결됨 · 방화벽 켜짐 · 경고 3건 · SDP 미연결」은 설명용 예시이며 내 PC 값이 아닙니다. 이 기능에는 예시 값이 없고, `npm run demo`에서도 PC 값은 실제로 읽습니다(SDP 칸만 「예제 자료(SDP 연결 아님)」).

### 동작
- **핵심 3가지**(기록 보기 → 내 PC 상태 → 위험 알림): 각각 지금 됨/아직 안 됨. 「내 PC 상태로 이동」, 「알림 목록으로 이동」 버튼은 해당 칸으로 포커스를 옮김. 「기록 보기」는 왼쪽 메뉴 「보안 기록」에 있음

- **오류 화면**: `실패한 항목 · 이유 · 다음에 할 일`을 적음. 일부만 실패하면 읽은 항목은 그대로 두고 실패한 항목만 오류 화면에 표시. 예시 값이나 이전 값으로 대신 보여 주지 않음
- **키보드**: 모든 버튼은 Tab으로 이동하고 Enter 또는 Space로 실행. 포커스 표시(보라색 테두리)가 있고, 결과 칸은 `aria-live`로 변경을 알림

|---|---|
| 서버에 연결하지 못했습니다 | 앱 폴더에서 `npm start`로 서버가 켜져 있는지 확인한 뒤 다시 조회 |

- 모두 전달받은 내용이며 내가 직접 지켜본 것이 아님.
- 증명되는 범위: 다른 사람이 수정본 안내를 따라 서버를 켜고 API 응답까지 확인함.

### 같은 결과를 다시 만드는 순서(별도 화면)
1. 켜 둔 서버가 있으면 `Ctrl+C`로 끄고 `npm start`로 다시 켜기(서버 파일 목록이 바뀌어서 재시작이 필요)
2. `http://127.0.0.1:5189/pc` 열기, 또는 첫 화면의 「내 PC 점검 화면 열기 ↗」
3. 「PC 상태 다시 조회」를 두 번 눌러 「이전 조회 대비」와 추이 표 2행 확인
