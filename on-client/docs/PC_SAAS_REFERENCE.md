# 내 PC와 서비스 상태를 보는 개인 클라이언트 만들기 (참고 가이드)

이 문서는 ZTNA/XDR 개인 클라이언트를 만드는 학생이 참고할 사례입니다. 새 앱이나 메뉴를 만들지 않고, 지금 쓰는 `student/extension.mjs`의 `createStudentView({ api, onChange })` 계약 안에서 이어 갑니다. 참고 코드는 `examples/pc-saas/student-extension.mjs`, 시험 방법은 [`examples/pc-saas/README.md`](../examples/pc-saas/README.md)에 있습니다.

참고 코드와 이 문서는 자동 성취가 아닙니다. 그대로 옮긴 코드는 단계 완료로 인정하지 않습니다.

## 이 문서의 경로는 앱 폴더를 기준으로 씁니다

앱 폴더는 `package.json`과 `student` 폴더가 함께 있는 곳입니다. 이 문서에 나오는 `student/extension.mjs`, `examples/pc-saas/…`, `docs/…`, `public/app.js` 같은 경로는 모두 앱 폴더에서 시작합니다.

- 저장소 전체를 받았다면 앱 폴더는 `education/on-client`입니다. 저장소 맨 위에서 보면 참고 코드는 `education/on-client/examples/pc-saas/student-extension.mjs`입니다.
- 시작 틀 압축본을 풀었다면 압축본 안의 `on-client` 폴더가 앱 폴더입니다. 다른 이름의 폴더에 풀었더라도 `package.json`과 `student` 폴더가 함께 있는 곳을 찾으면 됩니다.

이 사례에서 학생이 읽을 자료는 앱 폴더 안의 두 가이드(이 문서와 [`PC_SAAS_SOURCES.md`](PC_SAAS_SOURCES.md))와 [`examples/pc-saas/README.md`](../examples/pc-saas/README.md), 참고 코드 `examples/pc-saas/student-extension.mjs`입니다. 서비스별 공식 근거는 `PC_SAAS_SOURCES.md`에 적힌 공식 문서 링크로 이어집니다.

## 완성할 핵심 기능은 세 가지입니다

1. **내 PC 점검** — 이 앱이 실행된 PC의 실제 상태(`/api/pc/status`)를 측정 시각과 함께 보여 줍니다.
2. **서비스 연결 · 사용량 · 비용** — 내가 쓰는 서비스의 연결 상태, 관측한 계정 보안 항목, 사용량, 월 비용, 취약점 근거를 보여 줍니다.
3. **이상 징후 근거** — 위 두 기능에서 나온 관찰을 출처·시각·한계와 함께 모아 보여 줍니다. 판정이 아니라 근거입니다.

최소 요건으로 SDK 전체나 네 서비스(GitHub·Vercel·Railway·Supabase) 실연동을 요구하지 않습니다. **서비스 1개부터** 끝까지 정확하게 만드는 것을 권장합니다.

ZTNA는 이 사례에서 **접속 신뢰 근거를 보여 주는 모니터링**까지입니다. 실제 네트워크 차단, 보안 인증, 기업용 XDR 완성이라고 쓰지 않습니다.

## 일정과 이 가이드의 관계

마무리 기간은 **한국 시간 2026년 10월 26일(월) 00:00부터 11월 6일(금) 23:59까지**입니다. 아래 7일은 **권장 작업 순서**이며 기간의 길이와 다릅니다. 하루에 하나씩 하지 않아도 되고, 며칠을 합쳐도 됩니다. 기간이 지나도 앱과 기존 제출·제작 안내는 막히지 않습니다. 끝내지 못한 날은 다음 날 이어서 합니다.

## 7일 권장 작업 순서

| 순서 | 할 일 | 끝났다고 볼 수 있는 상태 |
|---|---|---|
| 1일차 | 내 프로젝트를 커밋하고, 별도 복사본에서 참고 코드를 켜 봅니다. 「개발 참고」를 펼쳐 「학생 API로 내 PC 실측 조회」를 누르고, 결과가 실측인지 「지원 없음」인지 `public/app.js`의 `STUDENT_GET_PATHS`에서 확인합니다(아래 「앱 판에 따라 달라지는 것」). | 원래 프로젝트가 그대로이고, 내 PC 값이 어디서 오는지 설명할 수 있습니다. |
| 2일차 | **내 PC 점검**을 내 코드로 만듭니다. 제공 카드 「내 PC 상태」의 결과를 기준으로, 학생 계약에서 받을 수 있는 자료와 받을 수 없는 자료를 나눠 표시합니다. | 조회 성공·확인 불가·오래됨·실패가 화면에서 서로 다르게 보입니다. |
| 3일차 | 서비스 **1개**를 고르고, 연결 전 화면부터 만듭니다. 모든 칸이 「연결 전 · 확인 불가」로 시작합니다. | 아무것도 연결하지 않은 상태에서 0원·정상·안전이 하나도 보이지 않습니다. |
| 4일차 | 고른 서비스 1개를 실제로 연결합니다. 비밀값은 서버 쪽에만 두고 화면·브라우저에 저장하지 않습니다. 담당자가 허용한 방법으로만 연결합니다. | 조회 성공·권한 부족·부분 결과·실패가 각각 다르게 표시됩니다. |
| 5일차 | 그 서비스의 **사용량과 월 비용**을 아래 비용 규칙대로 붙입니다. | 금액 옆에 청구월·통화·집계 기간·실적/예상·크레딧·세금·출처가 모두 있습니다. |
| 6일차 | **이상 징후 근거**를 모읍니다. PC 관찰과 서비스 관찰을 출처·시각·한계와 함께 나열합니다. | 각 항목에 「무엇을 봤는지」와 「그것만으로 말할 수 없는 것」이 함께 있습니다. |
| 7일차 | 처음 받은 PC에서 실행하듯 다시 켜서 세 기능을 확인하고, 실패 화면도 일부러 만들어 봅니다. 시간이 남으면 두 번째 서비스를 붙입니다. | 연결이 끊기거나 권한이 없을 때도 화면이 안전·정상으로 바뀌지 않습니다. |

정체성(로그인·기기·세션), 접속 이벤트, 조치는 이 사례가 해결하지 않습니다. 기존 단계의 **학생 구현 과제**로 그대로 남습니다.

## 상태는 일곱 가지로 나눠 보여 줍니다

| 상태 | 뜻 | 화면에서 하지 말 것 |
|---|---|---|
| 조회 성공 | 이번 요청에서 값을 읽었습니다. 출처와 시각을 같이 보여 줍니다. | 시각 없이 값만 보여 주기 |
| 권한 부족 | 읽을 권한이 없어 값을 받지 못했습니다. | 「항목 없음」이나 「꺼짐」으로 바꾸기 |
| 부분 결과 | 일부만 읽었습니다(예: 일부 집계, 한 프로젝트만). | 전체 결과처럼 보여 주기 |
| 오래됨 | 값은 있지만 정한 시간보다 오래됐습니다. | 현재 상태로 보여 주기 |
| 확인 불가 | 조회하지 않았거나 응답 형식을 확인하지 못했습니다. | 정상·안전으로 판정하기 |
| 예시 | 사용자가 「예시 보기」를 눌렀을 때만 보이는 고정 값입니다. | 표시 없이 섞기, 기본으로 켜 두기 |
| 실패 | 요청이 실패했습니다(시간 초과, 네트워크 오류 등). | 이전 값을 그대로 남겨 두기 |

연결을 아직 만들지 않은 서비스는 「연결 전」으로 시작하고, 그 안의 모든 값은 「확인 불가」입니다.

## 비용 표시 규칙

- 금액에는 **청구월, 통화, 집계 기간, 실적인지 예상인지, 크레딧 반영 여부, 세금 포함 여부, 출처**를 함께 적습니다.
- 확인하지 못한 금액은 **「확인 불가」**로 씁니다. **0원으로 쓰지 않습니다.**
- 남은 잔액이나 크레딧을 추정해 만들지 않습니다. 서비스가 알려 준 값만 씁니다.
- 통화가 다른 서비스의 금액을 합치지 않습니다. 합치려면 환율과 그 출처를 따로 적습니다.
- 청구 주체(개인·조직·팀), 대상 프로젝트, 조회 시각을 함께 적고 조직 총액과 그 안의 프로젝트 비용을 중복 합산하지 않습니다. 실적과 월말 예상도 합치지 않습니다. 출처와 범위를 확인한 실제 0은 표시할 수 있습니다.

공식 연결 근거와 서비스별 권한·집계 범위는 [`PC_SAAS_SOURCES.md`](PC_SAAS_SOURCES.md)를 참고하세요. 공개 공급자 상태 페이지는 개인 계정의 권한·비용·보안을 확인한 결과가 아닙니다.

## 보안 표시 규칙

- **관측한 항목별 근거만** 보여 줍니다(예: 「2단계 인증: 켜짐 · 출처 · 시각」). 여러 항목을 묶은 종합 보안 점수를 만들지 않습니다.
- 「취약점 발견 없음」은 **조회한 정확한 버전, 출처, 조회 시각, 범위**에만 해당한다고 함께 씁니다. 다른 패키지나 조회하지 않은 항목까지 안전하다고 쓰지 않습니다.
- 조회하지 않은 항목과 인증에 실패한 항목은 안전으로 판정하지 않습니다.
- OSV 같은 취약점 데이터베이스 실제 연동은 **추후 학생 과제**입니다. 참고 코드에는 들어 있지 않습니다.

## 내 PC 데이터를 읽을 때 지킬 것

참고 코드에서 관찰 기준으로 삼는 항목은 CPU·메모리·디스크·Windows 방화벽·Windows 기록 다섯 개입니다. 화면의 실측 `3/5` 같은 표시는 이 다섯 항목의 수집 범위입니다. 네트워크 구성 요약은 위쪽 제공 카드에서 별도로 확인합니다. Windows 기록이 최대5,000건의 일부 집계이면 관찰이0건이어도 그 한계를 요약에 함께 표시합니다.

- 메모리 사용량이 높다는 것만으로 악성코드라고 판정하지 않습니다.
- Windows 방화벽이 켜져 있다는 것만으로 안전하다고 판정하지 않습니다. 세 프로필이 모두 켜진 것은 이상 징후 목록에 넣지 않고, 꺼진 프로필만 관찰로 적습니다.
- Windows 오류 기록 건수는 침해 판정이 아닙니다. 기록 본문은 이 조회에 들어 있지 않습니다.
- CPU 값은 200ms 표본 한 번입니다. 원인을 말하려면 어떤 프로그램인지 더 확인해야 합니다.
- 조회하지 못한 항목은 「확인 불가」로 남깁니다. 응답이 성공한 것과 항목마다 값을 실제로 읽은 것은 다릅니다. 「실측 3/5 · 확인 불가 2개」처럼 나눠 쓰고, 항목을 하나도 읽지 못했으면 성공이라고 쓰지 않습니다.
- 관찰이 0건이어도 「이상 없음」이나 안전 판정으로 쓰지 않습니다.

## 앱 판에 따라 달라지는 것

`/api/pc/status`는 서버에 이미 있는 읽기 전용 GET 경로이고, 제공 카드 「내 PC 상태」가 직접 읽습니다. 학생 확장에서 이 경로를 읽을 수 있는지는 내 앱 폴더의 `public/app.js`에 따라 다릅니다. 버전 이름만 보고 판단하지 말고, 내 `public/app.js`의 `STUDENT_GET_PATHS`를 직접 열어 확인합니다.

| 앱 판 | `studentApi.get('/api/pc/status')`의 결과 | 학생 화면에서 할 일 |
|---|---|---|
| 0.2.17까지의 제공 소스 | 허용 목록에 없어 `NOT_ALLOWED`가 돌아옵니다. | 「지원 없음」으로 안내하고 제공 카드를 가리킵니다. 실패로 보이지 않게 따로 처리합니다. |
| 0.2.18 후보(아직 배포 전) | 허용 목록에 이 경로 하나가 추가될 예정입니다. 제공 카드와 같은 실측 응답이 기존 응답 형식(`ok`·`data`·`meta`) 그대로 돌아옵니다. | 버튼을 누를 때 받은 실측을 내 화면에 보여 주고, 조회 성공·확인 불가·오래됨·실패를 나눕니다. |

0.2.18 후보에서 예정된 계약은 아래와 같습니다. 배포 시기와 내 PC에 실제로 깔렸는지는 이 문서가 확인하지 않습니다.

- 정확히 `/api/pc/status` 한 줄만 추가됩니다. 뒤에 `?…`를 붙이거나, 끝에 `/`를 붙이거나, `http://…`로 시작하는 전체 주소를 쓰면 요청을 보내기 전에 `NOT_ALLOWED`로 돌아옵니다. GET 외의 방법은 없습니다.
- 이 경로를 동시에 여러 번 불러도 진행 중인 조회 하나를 같이 씁니다. 그 조회가 끝나면(성공·실패 모두) 다음에 부를 때 새로 읽습니다. 앱이 끝난 결과를 보관하거나 스스로 다시 읽지 않습니다.
- 내 원래 `student/extension.mjs`는 새 판이 나와도 자동으로 덮어쓰지 않습니다. 참고 코드를 쓰려면 아래 「예제와 내 작업을 섞지 않는 방법」대로 직접 옮깁니다.
- 내려받은 압축본이 정말 그 판인지는 버전 이름이 아니라 배포 담당자가 알려 준 정확한 파일과 서명으로 확인합니다. 그 확인은 배포 담당자가 맡습니다.

### PC 실측을 언제 읽을지

- 기본은 **사용자가 버튼을 누를 때 한 번** 읽는 수동 조회입니다. 화면을 다시 그리거나 `onChange`가 불릴 때 조회를 시작하지 않습니다. 그렇게 하면 다시 그리기와 조회가 서로를 부르며 끝없이 돌 수 있습니다.
- 자동으로 다시 읽고 싶다면 **10초 이상** 간격을 권장합니다. 제공 카드의 「10초마다 확인」과 같은 기준이며, CPU 표본과 Windows 기록 집계가 매번 PC에서 다시 돌기 때문입니다. 참고 코드는 자동 조회를 구현하지 않았습니다.
- 받은 자료를 그대로 보여 주는 것만으로는 성취가 아닙니다. 관찰과 한계를 내 말로 나누어 보여 주는 것이 과제입니다.

## 지금 계약에서 할 수 있는 것과 없는 것

- 0.2.17까지 `studentApi.get`이 허용하는 주소는 `public/app.js`의 `STUDENT_GET_PATHS`에 있는 여섯 개(`/api/me`, `/api/apps`, `/api/events`, `/api/devices`, `/api/sessions`, `/api/vulnerabilities`)뿐입니다. 0.2.18 후보에서는 위 표처럼 `/api/pc/status` 하나가 더해질 예정입니다.
- 어느 판에서든 다른 주소를 만들거나 직접 `fetch`로 우회하지 않습니다.
- 학생 화면은 서버나 외부에서 온 글자를 `textContent`로만 넣습니다. `innerHTML`을 쓰지 않습니다. 앱 화면의 보안 정책상 `style` 속성 대신 기존 CSS 클래스(`card`, `event`, `kv`, `state state-…`, `tag tag-student`, `tag tag-demo`, `muted`)를 씁니다.
- 학생 모듈은 `/student/extension.mjs` 한 파일만 서빙됩니다.
- 앱은 이 칸을 `onChange`뿐 아니라 연결 상태가 바뀔 때도 다시 그리고, 그때마다 칸 내용을 통째로 바꿉니다. 펼침 상태와 초점을 지키려면 내 코드에서 기억해 두었다가 되살려야 합니다.

## 학생이 덜 헤매도록 화면을 나누는 방법

참고 코드는 「요약 → 서비스별 요약 → 펼칠 때만 근거 상세 → 개발 참고」 순서로 보여 줍니다. 내 코드도 같은 생각으로 만들면 됩니다.

- 처음 보이는 곳에는 **핵심 상태와 다음 행동**을 둡니다. 출처·시각·기간·크레딧·세금 같은 상세 근거는 `details`/`summary`로 펼쳐 볼 수 있게 합니다. 부분 권한·비용 미확인·오래된 자료처럼 해석에 영향을 주는 한계는 요약에서도 보이게 남깁니다.
- 서비스마다 이름, 실제/예시 표시, 연결 상태, 비용과 보안·취약점을 확인했는지는 접지 않고 항상 보입니다. 연결 전 서비스의 보안·취약점은 「확인 불가」이며 「발견 없음」이 아닙니다.
- 비어 있는 상태와 실패한 상태는 다른 문구로 보여 주고, 둘 다 다음에 할 일을 한 문장으로 적습니다.
- 알림(`role="status"`)은 사용자가 누른 버튼의 결과 문단에만 붙입니다. 서비스 칸마다 알림을 걸지 않습니다.
- 이 예제는 다시 그릴 때 버튼도 교체하므로, 같은 조작부에 초점을 복원할 수 있도록 진행 중임을 글자와 `aria-disabled`로 알립니다. 중복 실행은 코드에서 막습니다. 모든 로딩 버튼이 이 방식을 써야 한다는 뜻은 아닙니다.

화면을 나누는 기준은 이 문서와 [`examples/pc-saas/README.md`](../examples/pc-saas/README.md)에 있고, 서비스별 권한·집계 범위의 근거는 [`PC_SAAS_SOURCES.md`](PC_SAAS_SOURCES.md)의 공식 문서 링크로 이어집니다. 이 사례를 만들 때 쓴 내부 조사 기록은 시작 틀에 들어 있지 않으며, 과제를 하는 데 필요하지 않습니다.

## 예제와 내 작업을 섞지 않는 방법

참고 코드는 별도 복사본에서만 켜 보고, 내 프로젝트에는 내 말로 다시 씁니다. 복사본의 앱 폴더 안에서 `examples/pc-saas/student-extension.mjs`를 `student/extension.mjs` 자리에 넣어 켜 보고, 원래 프로젝트의 `student/extension.mjs`는 그대로 둡니다. 복사, 앱 폴더에서 실행하는 비교(`git diff --no-index`), 실수로 덮었을 때 되살리는 방법은 [`examples/pc-saas/README.md`](../examples/pc-saas/README.md)에 있습니다.

시작 틀 0.2.17의 파일 목록에는 이 문서, `docs/PC_SAAS_SOURCES.md`, `examples/pc-saas/README.md`, `examples/pc-saas/student-extension.mjs` 네 파일이 들어가도록 정해져 있습니다. 내가 받은 압축본에 실제로 들어 있는지, 언제 배포되는지, 설치 묶음(`package-app`)에 들어 있는지는 이 문서가 확인하지 않았습니다. 들어 있다고 가정하지 말고 내 앱 폴더에서 직접 확인하세요.
