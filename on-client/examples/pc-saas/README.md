# 내 PC와 서비스 상태를 함께 보는 참고 사례

이 폴더의 `student-extension.mjs`는 학생이 읽고 자기 코드로 다시 만드는 **참고 코드**입니다. 자동 성취가 아니며, 그대로 붙여 넣은 변경을 단계 완료로 인정하지 않습니다. 저장소 전체에서 작업한다면 같은 규칙이 `education/on-client/AGENTS.md`의 「제공 코드를 성취로 인정하지 않는다」에도 있습니다. 시작 틀 압축본에는 그 파일이 들어 있지 않습니다.

전체 7일 작업 순서와 상태 구분 규칙은 [`docs/PC_SAAS_REFERENCE.md`](../../docs/PC_SAAS_REFERENCE.md)에 있고, 서비스별 공식 근거는 [`docs/PC_SAAS_SOURCES.md`](../../docs/PC_SAAS_SOURCES.md)의 공식 문서 링크로 이어집니다.

## 경로는 앱 폴더를 기준으로 씁니다

앱 폴더는 `package.json`과 `student` 폴더가 함께 있는 곳입니다. 아래 경로는 모두 앱 폴더에서 시작합니다.

- 저장소 전체를 받았다면 앱 폴더는 `education/on-client`입니다. 이 예제는 저장소 맨 위에서 `education/on-client/examples/pc-saas/student-extension.mjs`에 있습니다.
- 시작 틀 압축본을 풀었다면 압축본 안의 `on-client` 폴더가 앱 폴더입니다. 이 예제는 그 안의 `examples/pc-saas/student-extension.mjs`에 있습니다.

## 이 예제가 하는 것과 하지 않는 것

| 하는 것 | 하지 않는 것 |
|---|---|
| 기존 `createStudentView({ api, onChange })` 계약으로 `renderStatus` 칸 하나를 채웁니다. | 새 앱·페이지·메뉴·서버 주소·권한을 만들지 않습니다. |
| 내 PC 값은 위쪽 제공 카드 「내 PC 상태」에서 보도록 짧게 안내합니다. 접혀 있는 「개발 참고」를 펼친 뒤 「학생 API로 내 PC 실측 조회」를 누를 때만 기존 읽기 전용 경로 `api.get('/api/pc/status')`를 부릅니다. 0.2.18 후보 앱에서는 제공 카드와 같은 실측을 받아 보여 주고, 이 경로를 허용하지 않는 이전 판 앱에서는 「지원 없음」으로 따로 안내합니다. | `fetch`로 직접 부르거나 다른 경로로 PC 값을 읽지 않습니다. 화면을 다시 그릴 때나 `onChange`에서 조회하지 않고, 자동으로 되풀이해 읽지 않습니다. |
| GitHub·Vercel·Railway·Supabase를 「연결 전 · 확인 불가」로 보여 줍니다. | 키·토큰 입력, 브라우저 저장, 외부 요청, 인증을 구현하지 않습니다. |
| 「예시 보기」를 누를 때만 고정 예시를 보여 주고, 서비스 요약과 근거 상세에 `[예시]`를 붙입니다. 예시의 취약점 항목은 가상 패키지 이름을 씁니다. | 가짜 정상, 가짜 잔액, 종합 보안 점수, 서비스 금액 합계를 만들지 않습니다. |
| 화면에는 `textContent`만 씁니다. | `innerHTML`이나 `style` 속성을 쓰지 않습니다. |
| 정체성·판정·이벤트·조치 칸은 기존 「학생 구현 대기」 문구를 그대로 둡니다. | 그 칸들을 해결한 것처럼 보이게 하지 않습니다. |

ZTNA 범위는 **접속 신뢰 근거를 보여 주는 모니터링**까지입니다. 실제 네트워크 차단, 보안 인증, 기업용 XDR 완성을 뜻하지 않습니다.

## 화면은 요약부터 보이고 근거는 펼칠 때만 보입니다

「학생 상태·알림 표시」 칸 하나 안에서 아래 순서로 보입니다.

1. **지금 상태 요약** — 내 PC를 어디서 보는지, 서비스 연결 상태, 이상 징후 근거 수, 다음 행동을 네 줄로 보여 줍니다.
2. **서비스별 연결 · 사용량 · 비용** — 서비스마다 이름, 실제/예시 표시, 연결 상태, 사용량 상태, 비용과 보안·취약점을 확인했는지만 보입니다.
3. **근거 상세** — 예시를 켰을 때 서비스마다 「근거 보기」를 펼치면 출처·시각·기간·크레딧·세금·취약점 근거가 나옵니다.
4. **이상 징후 근거**와 **개발 참고** — 둘 다 처음에는 접혀 있습니다. 내 코드로 PC 실측을 받아 보는 버튼과 남은 과제는 개발 참고 안에 있습니다. 조회한 실측의 관찰은 요약과 이상 징후 근거에도 「실측 n/5 · 확인 불가 m개」 형태로 이어집니다.

펼침은 브라우저 기본 `details`/`summary`를 씁니다. 앱이 이 칸을 다시 그려도 펼친 항목과 이 칸 안에 있던 초점을 되살립니다. 사용자가 이미 다른 곳으로 초점을 옮겼다면 초점을 가져오지 않습니다. 기본 Enter·Space·Tab 조작과 초점 유지는 실제 PC Chrome에서 확인했고, NVDA 같은 화면 읽기 프로그램의 사용성은 아직 검증하지 않았습니다.

## 실제 API 계약을 확인한 근거

- `/api/pc/status`는 `src/server.mjs`에 있는 실제 읽기 전용 GET 경로이고, 제공 카드(`public/pc-status-view.mjs`)가 직접 읽습니다.
- 0.2.17까지의 `public/app.js`는 `STUDENT_GET_PATHS`에 `/api/me`, `/api/apps`, `/api/events`, `/api/devices`, `/api/sessions`, `/api/vulnerabilities`만 둡니다. 여기에 없는 주소는 `NOT_ALLOWED`로 돌아오고, 예제는 이것을 「지원 없음」으로 보여 줍니다.
- 0.2.18 후보(아직 배포 전)의 `public/app.js`는 같은 목록에 정확히 `/api/pc/status` 하나를 더합니다. `?…`·끝 `/`·전체 주소는 요청 전에 `NOT_ALLOWED`이고, 동시에 여러 번 불러도 진행 중인 조회 하나를 같이 쓰며, 끝난 결과를 보관하지 않습니다. 내 `public/app.js`를 직접 열어 어느 쪽인지 확인합니다. 버전 이름만으로 판단하지 않습니다.
- 학생 모듈은 `/student/extension.mjs` 한 파일만 서빙됩니다(`src/server.mjs`의 `files`). 이 `examples` 폴더는 서빙되지 않으므로 예제는 한 파일로 만들었습니다.
- 예제의 실측·실패·오래된 응답·부분 결측·0건 표시는 합성 응답으로만 시험합니다. 실제 학생 PC에서 0.2.18 후보로 받은 결과는 아직 확인하지 않았습니다. 예시 서비스 값은 실측이 아니며, 서비스 4개를 실제로 연결한 것이 아닙니다.

## PC 실측을 읽는 때

- 기본은 버튼을 누를 때 한 번 읽는 수동 조회입니다. 진행 중에는 같은 버튼을 다시 눌러도 새로 부르지 않습니다.
- 자동으로 다시 읽게 만들고 싶다면 10초 이상 간격을 권장합니다(제공 카드의 「10초마다 확인」과 같은 기준). 이 예제는 자동 조회를 넣지 않았습니다.
- 받은 실측을 그대로 보여 주는 것만으로는 성취가 아닙니다. 「실측 3/5 · 확인 불가 2개」, Windows 기록 최대 5,000건 일부 집계, 관찰 0건이 「이상 없음」이 아니라는 점을 내 말로 나누어 보여 주는 것이 과제입니다.

## 내 프로젝트를 건드리지 않고 시험하는 방법

예제는 **별도 복사본**에서만 켜 봅니다. 내 원래 프로젝트의 `student/extension.mjs`를 예제로 덮어쓰지 않습니다.

1. 내 프로젝트의 변경을 먼저 커밋합니다.
2. 내 프로젝트 폴더 전체를 새 폴더로 복사합니다. 저장소 전체를 받았다면 저장소 폴더를, 시작 틀만 받았다면 앱 폴더를 복사합니다. 예: `C:\내 작업\pc-saas-시험`. 원래 폴더는 그대로 둡니다.
3. **복사본의 앱 폴더** 안에서만 `examples/pc-saas/student-extension.mjs`를 `student/extension.mjs` 자리에 복사합니다. 저장소 전체를 복사했다면 복사본의 `education/on-client`가 앱 폴더입니다. 복사본의 앱 폴더에서 PowerShell로 하면 아래와 같습니다. 원래 프로젝트 폴더에서는 실행하지 않습니다.

   ```powershell
   Copy-Item -LiteralPath examples\pc-saas\student-extension.mjs -Destination student\extension.mjs
   ```

4. 복사본에서 평소처럼 앱을 켜고 「학생 상태·알림 표시」 칸을 봅니다.
5. 다 본 뒤에는 시험 앱을 종료합니다. 복사본에서는 커밋하거나 제출하지 않습니다.

### 내 코드와 비교하기

내 원래 프로젝트의 **앱 폴더**(저장소 전체라면 `education/on-client`, 시작 틀이라면 `package.json`과 `student` 폴더가 함께 있는 폴더)에서 아래 명령을 실행하면 예제와 내 파일이 어떻게 다른지 읽기만 합니다. 파일을 바꾸지 않습니다. 두 경로는 모두 앱 폴더 기준 상대 경로이므로, 저장소 맨 위에서 실행하면 파일을 찾지 못합니다. 내 프로젝트에 `examples` 폴더가 없으면 예제 파일을 받아 둔 실제 경로를 두 번째 자리에 넣습니다.

```powershell
git diff --no-index -- student/extension.mjs examples/pc-saas/student-extension.mjs
```

필요한 부분은 **내 말과 내 구조로 다시 씁니다.** 예제 전체를 붙여 넣으면 이미 만든 내 `renderIdentity`·`renderEvents`·`renderAction` 등이 기존 「학생 구현 대기」 문구로 덮입니다.

### 실수로 덮어썼을 때

- 먼저 현재 파일도 다른 이름으로 복사해 보존합니다. 원래 프로젝트 파일과 마지막 커밋을 읽기만 하며 비교하고, 복구할 커밋에 내 작업이 실제로 들어 있는지 확인합니다.
- 사전 커밋에 내 작업이 전부 저장됐음을 확인한 경우에만, 담당 강사와 복구할 커밋을 지정해 시험 복사본의 파일을 되살립니다. 커밋하지 않은 변경이 남아 있으면 `git restore`를 바로 실행하지 않습니다.
- 어느 쪽도 확실하지 않으면 파일을 지우지 말고 담당 강사에게 현재 파일과 보존한 사본을 보여 줍니다. 이력을 지우는 명령(`reset --hard`, 강제 push)은 쓰지 않습니다.

## 포함과 배포에 대해

시작 틀 0.2.17의 파일 목록에는 이 README와 `student-extension.mjs`, 두 가이드(`docs/PC_SAAS_REFERENCE.md`, `docs/PC_SAAS_SOURCES.md`)가 들어가도록 정해져 있습니다. 내가 받은 압축본에 실제로 들어 있는지, 설치 묶음(`package-app`)에 들어 있는지는 이 문서가 확인하지 않았습니다. 들어 있다고 가정하지 말고 내 앱 폴더에서 직접 확인하세요. 배포 시기도 이 문서가 정하지 않습니다. 새 판이 나와도 내 `student/extension.mjs`는 자동으로 덮어쓰지 않습니다.
