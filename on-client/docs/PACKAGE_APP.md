# 내 앱 설치용 묶음 만들기

`package-app`은 학생 프로젝트를 읽어 설치용 ZIP과 파일별 SHA-256 목록, Windows 설치기를 새 폴더에 만듭니다. 학생 원본·student 폴더·꾸밈 파일·화면 코드를 바꾸지 않습니다. 제공 파일과 학생 작성·수정 파일은 목록의 `origin`으로 구분합니다. 기존 수료용 `export-student-package`와 별도 도구입니다.

## 한 명령으로 만들기 (기본: 설치형 전체 앱)

Node.js 22~24가 있는 Windows에서 프로젝트의 `on-client` 폴더로 이동한 뒤 한 명령을 실행합니다.

```powershell
npm run package-app -- --source . --out "C:\내 작업\내 앱 설치 묶음" --iconPath "C:\내 작업\승인받은 아이콘.png" --app-name "내 앱"
```

마무리 단계에서 결과를 올릴 때는 같은 명령 끝에 `--finish-materials`만 붙입니다. 작업을 먼저 커밋해야 합니다(커밋하지 않은 변경이 있으면 `PACKAGE_FINISH_COMMIT_REQUIRED`로 멈춥니다).

```powershell
npm run package-app -- --source . --out "C:\내 작업\내 앱 마무리 묶음" --iconPath "C:\내 작업\승인받은 아이콘.png" --app-name "내 앱" --finish-materials
```

이 명령은 **이 PC에 담당자가 미리 설치한 승인 실행 환경**(`%USERPROFILE%\.aleph-alekov-host\runtime\` 아래의 `runtime.zip`과 서명된 목록 `catalog.json`)을 찾아, 그 파일을 바이트 그대로 복사해 설치형 전체 앱 묶음(`alekov.install-package.v2`)을 만듭니다. 학생이 실행 환경 경로·해시·서명 파일을 따로 넣지 않습니다. 이 명령은 승인을 만들거나 대신하지 않습니다. 실행 환경이 승인된 것인지는 서버(C3)가 독립된 서명 목록으로 다시 확인하고, 설치된 앱은 따로 승인된 실행 host가 켜기 전에 다시 확인합니다.

승인 실행 환경이 없거나 하나로 정해지지 않으면 묶음을 만들지 않고 멈춥니다. 앱만 든 다른 형식으로 몰래 바꿔 만들지 않습니다. 원본은 그대로입니다.

| 메시지 코드 | 뜻 | 할 일 |
|---|---|---|
| `PROVIDED_RUNTIME_NOT_INSTALLED` | 이 PC에 승인 실행 환경이 아직 없음 | 담당자의 실행 환경 설치 안내를 기다립니다. |
| `PROVIDED_RUNTIME_AMBIGUOUS` | 승인 실행 환경 후보가 여러 개라 하나로 정하지 못함 | 메시지를 담당자에게 보여 줍니다. 파일을 지우지 않습니다. |
| `PACKAGE_RUNTIME_UNVERIFIED` | 실행 환경 파일이 목록과 맞지 않음 | 메시지를 담당자에게 보여 줍니다. |

세 경우 모두 담당자가 준비할 항목입니다. `--app-only-v1`로 형식을 바꾸거나 실행 환경을 직접 다시 설치하지 않습니다. 22단계 다음 권장 제작 기간에 포장·설치를 어느 순서로 하는지는 [FINAL_PRODUCT_GUIDE.md](FINAL_PRODUCT_GUIDE.md) 10장에 있습니다.

출력 경로의 상위 폴더는 있어야 하고 출력 폴더 자체는 아직 없어야 합니다. 원본 안이나 원본을 포함하는 경로에는 만들지 않습니다. 그림 입력 `--iconPath`는 꾸밈 파일에 `icon`이 없을 때 필수입니다. 256×256, 8비트 RGB/RGBA, 비인터레이스 PNG만 받습니다.

### 꾸밈 파일(`student/appearance.json`)이 있을 때

학생이 직접 만든 꾸밈 파일이 있으면 화면과 같은 검증기로 먼저 읽습니다(형식·예시는 `docs/STUDENT_PROMPTS.md` 마무리 단계 절). 꾸밈 파일과 그림은 다른 `student/` 파일처럼 `files` 목록의 경로·바이트 수·SHA-256(`origin: student`)으로만 묶입니다. 새 manifest 항목이나 승인 기록을 만들지 않습니다.

- `appName`이 있으면 포장 이름(바로가기·`INSTALL.md`·manifest `appName`)이 그 값입니다. `--app-name`은 빼도 되며, 적으면 같은 값이어야 합니다.
- `icon`이 있으면 `student/assets/brand-icon.png`가 바로가기 아이콘이 되고 manifest `icon.inputPngSha256`이 그 파일의 SHA-256입니다. `--iconPath`는 빼도 되며, 적으면 같은 바이트여야 합니다.
- 꾸밈 파일이 없으면 지금까지와 같습니다(`--iconPath` 필수, `--app-name`이 없으면 `케셰브`).

```powershell
npm run package-app -- --source . --out "C:\내 작업\내 앱 마무리 묶음" --finish-materials
```

| 메시지 코드 | 뜻 | 할 일 |
|---|---|---|
| `PACKAGE_APPEARANCE_INVALID` | 꾸밈 파일이나 그림이 규칙에 맞지 않음. 출력에 `file`(고칠 파일)·`field`·`reason`(이유 코드)이 함께 나옴 | 그 파일을 고친 뒤 다시 실행합니다. 도구는 학생 파일을 고치지 않습니다. |
| `PACKAGE_APPEARANCE_CONFLICT` | 명령의 `--app-name`·`--iconPath`가 꾸밈 파일과 다름(`file`·`field`·`reason` 포함) | 옵션을 빼거나 같은 값으로 맞춥니다. 어느 쪽도 몰래 고치지 않습니다. |

꾸밈의 미적 수준은 확인 기준이 아니며 F5(도구 품질 전용)와 통과·보류에 들어가지 않습니다. PNG 구조·CRC·압축 크기·행 필터를 확인하며, PNG 픽셀 바이트를 바꾸지 않고 ICO 컨테이너에 넣습니다. 새 그림 생성·크기 조정은 하지 않습니다. 실제 사용할 승인 그림이 없으면 그 그림의 품질·사용 승인은 미확인으로 남깁니다.

생성되는 파일은 다음과 같습니다.

- `app.zip`: `education/on-client/` 아래의 학생 앱과 아이콘. 학습 기능(`src/learning`)·격리 검수 도구·고정 계산기는 넣지 않습니다. 이것들은 승인 실행 환경이 제공합니다.
- `runtime.zip`: 이 PC의 승인 실행 환경을 바이트 그대로 복사한 것(고정 Node, 검증된 실행 환경, 공개 시작 기록, 서명된 앱 출시 정보).
- `APP_PACKAGE_MANIFEST.json`: 포함 파일·해시·크기·출처, 제외 목록, ZIP·설치기 해시, 실제 `runtime.zip` 바이트에서 계산한 실행 환경 목록(`fullAppRuntime`).
- `install-app.ps1`: 기존 설치·바로가기를 덮지 않는 설치기.
- `INSTALL.md`: 이 묶음의 실제 manifest 해시가 들어 있는 설치 명령.
- `--finish-materials`를 붙였을 때만: `finish.commit.raw`(커밋 원문), `finish.archive.tar.gz`(그 커밋의 소스 묶음).

마무리 화면에서는 **네 파일**을 각각 고릅니다: `finish.commit.raw`, `finish.archive.tar.gz`, `app.zip`, `APP_PACKAGE_MANIFEST.json`. 파일 이름을 바꾸거나 ZIP을 다시 만들지 않습니다. 네 파일은 한 번의 명령에서 나온 한 묶음이며 다른 폴더의 파일과 섞지 않습니다. `runtime.zip`은 올리지 않습니다. 서버가 manifest에 적힌 실행 환경을 자기 승인 목록에서 찾아 같은 바이트인지 확인합니다. 서버에 그 실행 환경이 없으면 등록하지 않고 「아직 준비되지 않음」으로 알립니다.

크기 한도: `app.zip` 70MiB, 파일 하나 10MiB, 앱 파일 합계 64MiB, 소스 묶음 25MiB, 실행 환경 `runtime.zip` 200MiB(그중 Node 150MiB, 다른 파일 각 2MiB, 256개 이하).

### 앱만 든 이전 형식 (`--app-only-v1`, 별도 경로)

`--app-only-v1`을 명시하면 실행 환경 없이 앱만 든 이전 형식(`alekov.install-package.v1`)을 만듭니다. 이 형식은 학습 기능과 고정 계산기(`api/_defense-race-model-copy.mjs`, SHA-256 `6f4a1e29610a626b80859310a977b06a8f66c5275063626c014ed5a4f4b4f7c2`)가 함께 있는 저장소 전체 개발 환경에서만 만들 수 있습니다. 시작 틀 0.2.15 프로젝트에는 학습 기능이 들어 있지 않으므로 `PACKAGE_RUNTIME_INCOMPLETE`로 멈춥니다. 기본 명령이 이 형식으로 자동 전환되는 일은 없습니다. 학생 마무리 포장에 쓰는 형식이 아니며, 기본 명령이 멈췄을 때 대신 쓰는 방법도 아닙니다.

## 새 폴더에 설치하기

`INSTALL.md`에 적힌 명령을 사용합니다. `-ManifestSha256` 값은 package-app이 출력한 값과 같아야 합니다. 설치 경로는 아직 없는 새 폴더입니다. 설치기가 그 안에 `education/on-client`와 `finish-runtime`을 만듭니다. 다른 설치나 원본의 개인 설정을 복사·공유하지 않습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install-app.ps1 -Destination "C:\Apps\내 앱" -ManifestSha256 <package-app이 출력한 해시> -CreateDesktopShortcut
```

바탕화면 바로가기는 `-CreateDesktopShortcut`을 명시할 때만 만듭니다. 같은 이름의 바로가기가 이미 있으면 설치 전에 멈춥니다. 시험용 `-DesktopDirectory`는 직접 소유한 별도 폴더를 지정하는 옵션이며, 바로가기 생성 요청 없이 사용할 수 없습니다. 설치 중 앱을 실행하지 않습니다. 설치기는 `runtime.zip`도 파일별 해시를 확인한 뒤 새 경로의 `finish-runtime` 아래에만 풉니다.

설치형 전체 앱의 바로가기는 앱 폴더 안의 실행기가 아니라 **이 PC의 승인된 실행 host**를 실행합니다.

```text
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "%USERPROFILE%\.aleph-alekov-host\start-installed-normal-app.ps1" -InstallRoot "<설치 경로>"
```

이 host가 이 PC에 없으면 설치기가 바로가기를 만들기 전에 멈춥니다(`INSTALL_NORMAL_APP_HOST_MISSING`). host 설치는 담당자가 준비할 항목이므로 설치 폴더를 그대로 두고 안내를 기다립니다. 설치 영수증 `INSTALL_RECEIPT.json`은 기록일 뿐이며 실행 방식을 고르지 않습니다. 영수증이 지워지거나 바뀌어도 바로가기는 같은 host로만 갑니다.

### 켜는 순서 (승인된 실행 host)

host는 다음 순서로 확인하고, 하나라도 실패하면 그 자리에서 멈춥니다. 일반 서버나 기존 개발용 실행으로 바꿔 켜지 않습니다.

1. `finish-runtime\app-release.json`의 서명을 host에 고정된 운영 앱 승인 키로 확인합니다. 설치 폴더·영수증·실행 환경 목록 안의 어떤 값도 승인을 대신하지 않습니다.
2. 실행 환경 목록, 고정 Node, Windows PowerShell, 시작 기록과 실행 환경의 모든 파일을 해시로 확인합니다.
3. 이 설치 전용 계정 연결 폴더 `%USERPROFILE%\.aleph-alekov-normal-<설치 경로 해시>`의 설정이 이 설치와 맞는지 읽기만으로 먼저 확인한 뒤, 승인된 준비 도구로 만들거나 다시 씁니다.
4. 같은 폴더의 SDP 설정 `sdp-host.json`을 확인합니다. 파일이 있으면 연결 방식으로, 그 자리에 아무것도 없으면 아래 「SDP 설정이 없을 때」의 방식으로 켭니다. 폴더나 링크(junction·깨진 링크 포함)가 있으면 멈춥니다.
5. 그 뒤에만 고정 Node로 앱을 켭니다(기본 포트 5189).

설치된 앱 폴더에서 `tools\start-alekov.ps1`을 직접 실행하면 「설치형 전체 앱은 바탕화면 바로가기(승인된 실행 host)로만 켭니다」로 멈춥니다. 학생 원래 프로젝트 폴더에서 하던 개발·연습 실행은 그대로입니다.

### SDP 설정이 없을 때 (이 PC 안에서만 쓰는 방식)

시작 틀 0.2.16의 설치형 앱은 SDP 설정 없이도 켤 수 있습니다. 조건은 하나입니다. host가 이 설치에 맞춰 정한 위치(`%USERPROFILE%\.aleph-alekov-normal-<설치 경로 해시>\sdp-host.json`)에 **아무 항목도 없어야** 합니다. 다른 경로를 지정하는 옵션은 없습니다. 이 경우에도 1~3단계의 서명·실행 환경·계정 연결 설정 확인과 앱 안의 학생 모듈·화면 확인은 모두 그대로 거칩니다.

- 켜지는 것: 내 PC 상태 보기(`/api/pc/status`), 학생이 만든 화면 확장과 꾸밈, 고정된 기존 화면 파일.
- 켜지지 않는 것: 계정 로그인, AI 연결, SDP 조회, 마무리 연결(finish). 화면의 진단에는 SDP가 「연결 안 됨」으로 나옵니다. 유료 AI나 외부 로그인은 호출하지 않습니다.
- 앱 결과 기록에는 `mode:"app-only-local"`, `finishCode:"FINISH_SDP_NOT_CONFIGURED"`가 남습니다.
- 앱을 켜는 도중에 SDP 파일이 생기면 방식을 몰래 바꾸지 않고 `FINISH_SDP_CONFIGURATION_CHANGED`로 멈추고 서버와 화면 복사본을 정리합니다. 다시 실행하면 그 파일로 연결 방식을 시도합니다.
- `sdp-host.json`이 있는데 비어 있거나, JSON이 깨졌거나, 읽을 권한이 없거나, 폴더·링크이면 이 방식으로 바꾸지 않고 멈춥니다. 잘못된 설정을 「없음」으로 취급하지 않습니다.

담당자가 SDP 설정 파일을 그 위치에 두면 다음 실행부터 연결 방식으로 켜집니다.

이 방식으로 켜지면 새 실행 화면은 머리글에 「내 PC 점검 모드」를 표시하고, 위쪽 「내 PC 확인」에서 이 PC의 여섯 항목(CPU, 메모리, 디스크, 네트워크 구성 요약, Windows 방화벽 세 프로필, 최근 24시간 Windows 기록)을 조회합니다. 자동 조회는 처음에 꺼져 있습니다. 쓸 수 없는 AI 연결 절차는 접히고 해당 버튼은 꺼지지만, 학생 화면 확장·꾸밈·기존 판정 기록·원문·권한은 그대로입니다. 화면에서 모드를 바꾸거나 키를 입력해 연결 기능을 여는 방법은 없습니다. 학생이 읽는 화면 설명은 [STUDENT_LAUNCH_GUIDE.md](STUDENT_LAUNCH_GUIDE.md) 10장에 있습니다.

시험0반(TEST0) 검증과 일반 학생 배포는 준비 상태가 다릅니다.

- **시험0반:** 저장소의 일반 앱 승인 정책(`scripts/lib/alekov-normal-app-policy.mjs`)에는 오너가 승인한 시험0반 공개 키 `aleph-test0-normal-app-r1` 하나가 들어 있습니다. host는 이 정책을 그대로 굳혀 넣으므로, 이 키로 서명된 출시 정보만 켭니다. 시험0반 PC에 host와 승인 실행 환경이 실제로 설치됐는지는 이 문서가 확인하지 않습니다. 그 PC의 검증 기록으로 판단합니다.
- **일반 학생 배포:** 오너가 정한 순서는 시험0반 검증 후 일반 학생 배포입니다. 공개 키의 이름만으로 반별 배포 승인 여부를 판단하지 않습니다. 현재 앱 승인 서명은 설치형 앱의 용도와 고정 실행 환경에 결속되며, SDP·계정·AI 권한은 별도입니다. 실제 시험0반 실행 검증, 학생용 도구 게시와 PC 배포가 끝났는지는 해당 배포 기록으로 확인합니다. 승인 실행 환경이 없는 PC에서는 `PROVIDED_RUNTIME_NOT_INSTALLED`로 멈추므로, 기존 프로젝트는 그대로 두고 배포 안내를 따릅니다.

### 마무리 연결과 AI

설치형 전체 앱 출시 자체는 AI 사용 권한을 주지 않습니다. 마무리 연결(finish)은 SDP 설정이 있고 별도 승인도 있을 때만 붙습니다. SDP 설정이 없으면 승인이 있어도 마무리 연결을 읽지 않습니다. 그 승인이 없거나 만료·회수돼도 앱·계정 연결·SDP와 이미 진행 중인 AI 요청은 그대로 이어집니다. 앱 창을 완전히 닫는 것만이 모두를 끝냅니다.

## 보존과 실패 처리

알려진 credentials/vault/registry·개인 설정·`.env`·Git·운영 DB·로그·캐시를 제외합니다. 비밀로 보이는 내용이 있으면 패키징을 중단하며 값을 출력하지 않습니다. 임의 이름의 모든 비밀이나 바이너리를 완전히 찾아낸다는 보장은 없으므로 공유 전 포함 목록을 확인합니다. 해시는 파일 일치 확인용이며 배포 주체를 인증하는 서명이 아닙니다. 설치형 전체 앱의 실행 승인은 위의 별도 서명 확인으로만 합니다.

링크·junction·hardlink와 위험한 압축 경로는 거절합니다. 설치기는 원본 ZIP·manifest를 읽는 동안 쓰기·교체를 막는 파일 핸들을 유지하고, 부모 폴더 핸들로 링크 경로 변경을 차단합니다. 새 경로와 파일은 배타적으로 만들고 파일별 해시를 확인합니다. 기존 원본이나 설치 경로는 덮어쓰지 않습니다.

실패한 부분 폴더는 자동 삭제하지 않습니다. `INSTALL_RECEIPT.json`의 `completed:true`가 없으면 설치 완료로 다루지 않습니다. 학생이 수정한 파일을 자동으로 원복하거나 지우지 않습니다. 부분 결과를 확인한 뒤 다른 새 경로로 다시 시도합니다. 실제 프로젝트를 지워서 재시도하지 않습니다.

패키징 끝에는 원본을 다시 조사해 파일 추가·삭제·수정과 제외 목록 변경을 대조합니다. 완료 manifest는 별도 파일로 기록·동기화한 뒤 배타적인 원자 게시를 수행합니다. Windows NTFS처럼 hardlink를 지원하는 출력 파일시스템이 필요합니다. 성공 시 임시 게시 링크는 제거하고 최종 manifest가 일반 단일 링크 파일인지 확인합니다. 지원하지 않는 파일시스템이나 같은 이름의 파일이 생긴 경우에는 덮어쓰지 않고 실패합니다.

출력 검사는 ZIP과 설치기뿐 아니라 생성한 `INSTALL.md`의 바이트도 다시 확인하고, manifest 게시 전후에 폴더의 파일 목록을 대조합니다. 안내가 바뀌거나 없어졌거나 예상하지 않은 파일이 생기면 성공으로 보고하지 않고 동시 작성자의 파일도 덮어쓰지 않습니다. 완료 후 같은 사용자 권한을 가진 다른 프로그램이 파일을 바꾸지 못하도록 격리하는 기능은 아닙니다.

`origin`은 `student/` 구분과 원래 starter manifest의 제공 파일 해시 대조에 따른 목록 정보입니다. 학생의 공식 성취나 코드 저작권을 인증하는 판정이 아닙니다. 공개된 0.2.14 시작 틀에는 이 포장 도구가 들어 있지 않습니다. 도구는 0.2.15부터 포함되며, 새 PC 점검과 설치형 미연결 실행은 0.2.16 시작 틀·승인 실행 환경의 배포 안내를 함께 따릅니다. 기존 학생 폴더를 지우지 말고 업데이트가 멈추면 그 메시지를 담당 강사에게 보여 줍니다.

## 포함 소스와 Git 이력 확인

기존 exporter의 계획에는 파일별 해시가 있지만 Git commit 정보는 없습니다. 이 도구는 임의의 `--commit` 값을 받지 않고 원본에서 실제 로컬 Git HEAD를 읽습니다. manifest의 `source.snapshot`은 포함한 앱 파일만 경로 순서로 정렬한 뒤 `경로 + NUL + 십진 바이트 수 + NUL + SHA256` 행을 LF로 연결해 UTF-8 SHA256을 구한 값입니다. 생성한 ICO와(앱만 든 이전 형식의) 외부 제공 계산기는 각각 별도 해시로 결속합니다. 설치기도 실제 파일 목록에서 이 digest를 다시 계산합니다.

`source.git`은 실제 HEAD·객체 형식·저장소 안의 상대 범위·HEAD 파일 트리 digest·현재 상태 digest를 별도로 기록합니다. 각 포함 파일의 원래 바이트로 Git blob ID를 계산한 결과는 `filesMatchHead`에 그대로 남깁니다. Git에서 무시된 학생 파일도 몰래 commit에 속한 것으로 처리하지 않습니다. 별도 `checkoutEquivalence`는 원래 바이트 일치(`raw-match`)와 Windows의 단순 LF→CRLF 체크아웃 변환(`verified-eol`)을 구분합니다. 후자는 저장소 상태가 깨끗하고 `core.autocrlf=true`, 적용 속성이 단순 텍스트 줄끝 변환이며, 변환한 바이트가 HEAD blob과 정확히 맞을 때만 기록합니다. 필터·인코딩·ident 변환이나 다른 변경이 섞이면 `unverified`로 둡니다. 이 검사는 원본을 고치거나 정규화하지 않습니다. 명령 출력과 `INSTALL.md`에도 이력 상태가 표시됩니다.

- Git이 없으면 `head:null`, `blocked-no-git`입니다. commit 검사는 `NOT_RUN`이며 commit을 만들어 넣지 않습니다.
- 미커밋 변경이 있거나 포함 파일이 HEAD에 없거나, 단순 줄끝 변환으로 설명되지 않는 차이가 있으면 `blocked-uncommitted`입니다. 개인 설치용 묶음은 만들 수 있지만 공식 제출에서는 차단해야 합니다.
- 원문 바이트가 맞거나 위의 단순 줄끝 변환만 확인되어도 `unverified`, `verified:false`, `requiresC3:true`입니다. **C3에서 제출 manifest와 실제 학생 commit의 일치·제출 요건을 별도로 검증해야 합니다.** C2 설치 성공만으로 공식 제출을 승인할 수 없습니다.

Git은 로컬 읽기 명령만 사용합니다. 잠금 없는 선택적 작업·index 갱신·fsmonitor·clean/process filter·하위 모듈 조사·lazy fetch를 차단하고 외부 Git 경로를 지정하는 환경변수도 물려받지 않습니다. 학생 commit·index·설정은 바꾸지 않습니다. 패키징 마지막에 소스와 Git 이력을 다시 확인하며, HEAD만 이동했어도 완료 manifest 게시를 중단합니다.

## 로컬 검사 범위

`node --test test/package-app.test.mjs`는 자기 소유 임시 프로젝트와 바탕화면 대체 폴더만 사용합니다. 기본 명령이 승인 실행 환경 없이 앱만 든 형식으로 바뀌지 않는지, `--app-only-v1` 경로의 ZIP·manifest·소스 보존, 변조·링크·경로 이탈, 요청한 바로가기와 기존 바로가기 보존, 부분 설치와 무해한 demo 서버 실행을 확인합니다. 시험용 PNG는 파일 형식 확인용 바이트 fixture이며 배포 그림이 아닙니다. 설치형 전체 앱의 연결 시험은 시험용 키·host·실행 환경만 쓰며 운영 승인 키나 운영 실행 환경을 쓰지 않습니다.

실제 학원 PC·실학생 원본·실제 승인 그림·Windows MCP·유료 AI·운영 플래그 활성화·자동 배포·학생 배포는 이 작업의 검수 범위가 아닙니다. 기존 17단계 AI_WAIT와 예약 PAUSED, 실학생 판정 승인 경계는 그대로입니다.

2026-10-20 로컬 확인 환경은 Node.js `v24.19.0`, Windows PowerShell `5.1.26100.9711`입니다. 실제 계정 기반 13~22와 격리 검수 실행은 `NOT_RUN`이며 기존 검수 환경 준비·승인 계약을 따릅니다. 통과 건수를 합산해 전체 suite 통과로 표현하지 않으며, 기존 전체 `npm test`는 실행하지 않습니다.
