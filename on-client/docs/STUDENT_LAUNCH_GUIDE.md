# 케셰브 시작·실행 안내 (학생용)

이 안내는 13~22단계에서 만드는 보안 Agent 앱 **케셰브**를 내 PC에서 처음 실행하고, 종료하고, 다시 실행하는 방법을 설명합니다.

- **케셰브**: 내 PC의 워크벤치 프로젝트 폴더 안에서 실행하는 보안 Agent 앱입니다. 13~22단계 동안 이 프로젝트 하나를 계속 고쳐 나갑니다. ALEPH 포털과 안내에서는 이 앱이 케셰브 또는 내가 정한 앱 이름으로 표시됩니다. 포털에서 이름을 바꿔도 이미 받은 프로젝트 파일과 실행 중인 앱 제목은 자동으로 바뀌지 않습니다.
- **CLCO**: AI 요청을 중계하는 서버(AI 게이트)입니다. 학생 프로젝트를 저장하는 곳이 아닙니다.
- **ALEPH**: 단계 안내를 읽고, 커밋한 코드를 제출하고, 판정 결과를 확인하는 곳입니다.

> 13단계 시작 틀은 ALEPH 4차 과제 화면의 「13단계 시작 틀 받기」에서만 받습니다. 다른 곳에서 받은 파일은 쓰지 않습니다.

## 1. 어느 폴더에서 시작하나요

| 내 상황 | 할 일 |
|---|---|
| 1~12단계 프로젝트가 있습니다 | 그 워크벤치 프로젝트 폴더에 시작 틀을 **추가**합니다. 기존 파일과 이전 기록은 지우거나 덮어쓰지 않습니다. |
| 3차를 마치지 못했거나 프로젝트가 없습니다 | 워크벤치에서 **새 프로젝트**를 만들고, 시작 틀로 13단계부터 시작합니다. |

- 어느 경우든 시작한 프로젝트 하나로 22단계까지 진행합니다. 단계마다 새 폴더를 만들지 않습니다.
- 개인 연습 폴더나 다른 사람의 폴더를 쓰지 않습니다.
- 시작 틀은 프로젝트 폴더 안의 `on-client` 폴더에 들어갑니다. 아래에서 **앱 폴더**는 이 `on-client` 폴더를 말합니다.
- Git 저장소의 최상위는 `on-client`가 아니라 그 위의 **프로젝트 폴더**입니다. 커밋과 제출 준비는 프로젝트 폴더 기준으로 진행합니다.

## 2. 처음 실행하기

준비할 것: Node.js 22~24(수업 기준 **24.19.0**). 없으면 https://nodejs.org 에서 설치한 뒤 PowerShell 창을 새로 엽니다.

1. 파일 탐색기에서 앱 폴더(`on-client`)를 엽니다.
2. 주소 표시줄에 `powershell`을 입력하고 Enter를 누릅니다. 그 폴더에서 PowerShell 창이 열립니다.
3. 아래 명령을 그대로 붙여 넣고 Enter를 누릅니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

4. 다음 두 줄이 보이면 실행된 것입니다.
   - `케셰브가 켜졌습니다. 브라우저에서 http://127.0.0.1:5189/ 을 여세요.` (예전에 받은 시작 틀에서는 앱 이름이 다르게 나올 수 있습니다.)
   - `서버가 응답한 것만 확인했습니다. AI 연결 상태는 화면에서 따로 확인해 주세요.`
5. 브라우저에서 `http://127.0.0.1:5189/`를 엽니다. 위쪽 상태 표시와 「보호 현황」 화면이 보이면 정상입니다.

`-ExecutionPolicy Bypass`는 이번 한 번의 실행에만 적용됩니다. PC의 보안 설정은 바뀌지 않습니다.

시작 틀 0.2.12부터는 실행 도구가 계정 연결용 개인 설정을 자동으로 준비합니다. 운영자에게 `native.json` 파일을 따로 받을 필요가 없습니다. 설정과 자격 보관소는 학생 프로젝트 밖의 Windows 사용자 폴더에 프로젝트별로 보관하며, 같은 프로젝트를 다시 실행하면 검증한 기존 설정을 사용합니다. 기존 파일이나 권한이 맞지 않으면 덮어쓰지 않고 안내합니다.

이 준비만으로 로그인이나 AI 연결이 완료되지는 않습니다. 앱의 「계정 연결 확인」에서 확인 번호를 보고, 같은 ALEPH 계정으로 승인한 뒤 앱에서 연결을 확인하세요. 이어서 앱의 AI 연결 승인과 연결 점검을 진행합니다. 제공 서버나 설정 파일에 다른 사람의 열쇠를 넣지 않습니다. 운영 연결이 아직 준비 중이면 오류를 성공으로 바꾸지 말고 담당자의 안내를 기다립니다.

연결 기능을 사용하지 않는 로컬 확인은 `-NoNativeHost`로 실행할 수 있습니다. `-Demo`는 예제 실행이며 자동 계정 연결 설정을 만들지 않습니다. 예전에 명시적으로 전달받은 `-NativeHostConfig` 설정도 계속 사용할 수 있습니다.

> **`tools\start-alekov.ps1` 파일이 없을 때**
> 예전에 받은 0.2 시작 틀에는 이 실행 도구가 없습니다. 이때는 같은 앱 폴더에서 `npm start`를 실행합니다. 주소는 `http://127.0.0.1:5189/`로 같습니다. 이 방법은 Node.js 버전과 포트를 미리 확인하지 않으므로, 오류가 나면 4장의 표에서 원인을 찾습니다.

## 3. 종료하기와 다시 실행하기

- **종료**: 앱을 실행한 PowerShell 창에서 `Ctrl+C`를 누릅니다. 브라우저에서 주소가 더 이상 열리지 않으면 종료된 것입니다.
- **다시 실행**: 같은 앱 폴더에서 2장의 명령을 다시 실행합니다. 실행과 종료는 내 파일을 바꾸지 않습니다.
- **창 없이 실행**: 명령 끝에 ` -Background`를 붙입니다. 화면에 안내된 「프로세스 번호」의 node를 작업 관리자에서 종료하면 꺼집니다.

## 4. 문제가 생겼을 때

아래 경우 모두 실행 도구는 다른 프로그램을 종료하거나, 무언가를 설치하거나, 파일을 지우지 않습니다. 원인을 해결한 뒤 같은 폴더에서 다시 실행합니다.

| 화면 메시지 | 할 일 |
|---|---|
| `Node.js 가 없습니다` | Node.js 24.19.0을 설치하고 PowerShell 창을 새로 연 뒤 다시 실행합니다. |
| `지금 Node.js 는 vXX 입니다` | Node.js 22~24 버전을 설치합니다. |
| `포트 5189 를 다른 프로그램이 쓰고 있습니다` | 그 프로그램은 그대로 둡니다. 명령 끝에 ` -Port 5190`을 붙여 실행하고, 브라우저 주소도 `:5190`으로 엽니다. |
| `앱 폴더가 아닙니다` 또는 `시작 틀 폴더가 아닙니다` | `on-client` 폴더 안에서 실행했는지 확인합니다. |
| `바로가기(링크)로 연결된 폴더` | 바로가기나 링크가 아닌 실제 폴더에서 실행합니다. |
| `…초 안에 뜨지 않았습니다` | 창의 메시지 전체를 강사에게 보여 줍니다. 필요하면 5장의 도움정보도 함께 보냅니다. |

실행 도구 밖의 계정 연결·AI 승인·기록 조회 오류는 [CONNECTION_TROUBLESHOOT.md](CONNECTION_TROUBLESHOOT.md)에서 오류 코드로 찾습니다.

## 5. 도움정보 복사

강사에게 현재 상태를 보여 줄 때 씁니다. 도움정보에는 비밀값(키·토큰)이 들어가지 않으며, 자동으로 어디에도 전송되지 않습니다.

1. 「보호 현황」 화면의 **도움정보** 칸에서 「도움정보 불러오기」를 누릅니다.
2. 표시된 내용을 직접 읽어 봅니다.
3. 「확인했으며 복사합니다」를 누른 뒤 강사에게 붙여 넣어 보냅니다. 자동 복사가 안 되면 선택된 내용을 `Ctrl+C`로 복사합니다.

AI 연결 문제는 **AI 연결** 칸의 「연결 도움정보 보기」를 같은 방법으로 씁니다.

## 6. 앱 안의 AI 연결은 별도입니다

- 앱이 실행됐다는 것은 내 PC의 서버가 응답했다는 뜻입니다. AI 연결에 성공했다는 뜻은 아닙니다.
- AI 연결은 화면의 **AI 연결** 칸 안내를 따릅니다. 주소나 키를 직접 입력하지 않습니다.
- 「예제」나 「연결 없음」 상태는 실제 연결 성공이 아닙니다.
- 여기서 말하는 AI 연결은 17단계부터 앱 화면 안에서 쓰는 AI입니다. 단계 통과를 정하는 공식 판정과는 다릅니다(8장). 앱 안 AI 연결이 되지 않아도 공식 판정은 따로 진행됩니다.

## 7. 시작 틀 업데이트

제공 파일이 바뀌면 **강사·운영자가** 업데이트를 적용합니다. 학생이 직접 하지 않습니다. 운영 절차는 [STARTER_UPDATE.md](STARTER_UPDATE.md)의 「운영 도구로 업데이트하기」를 따릅니다.

- 업데이트하기 전에 내 작업을 커밋해 되돌아갈 지점을 만들어 둡니다.
- 내가 고친 파일과 `student/` 폴더의 파일은 덮어쓰지 않고 「보존」으로 남깁니다.
- 업데이트는 파일을 지우지 않습니다.
- 결과를 확인하지 못하면 성공으로 보지 않습니다. 강사가 미리보기부터 다시 확인합니다.

## 8. 제출

단계를 마치면 아래 순서로 제출합니다. 자세한 화면 안내는 ALEPH 방어전 상황실의 「4차 방어전」 탭에 있습니다.

1. 프로젝트 폴더에서 이번 버전을 커밋합니다. origin에는 내 GitHub 저장소 주소가 등록돼 있어야 합니다. 저장만 하고 커밋하지 않은 변경은 제출되지 않습니다.
2. 워크벤치의 「포털 제출 준비」에서 단계를 고르고 「포털에서 제출 준비」를 누릅니다. 워크벤치가 커밋된 현재 버전(HEAD)의 코드를 묶어 포털 창으로 보냅니다.
3. 워크벤치에 「제출 준비 완료. 포털에서 내용을 확인하고 제출하세요.」가 보이면, 포털 창에서 저장소·커밋·단계를 확인하고 해당 단계의 제출 버튼(예: 「13단계 제출」)을 누릅니다.

워크벤치의 「포털에서 제출 준비」로 제출하면 GitHub 업로드(push)는 필요하지 않습니다. 서버는 받은 코드가 제출한 커밋과 같은지 Git 커밋 번호(해시)로 확인합니다. 내용이 맞지 않으면 불합격이 아니라 원문 확인 실패로 처리되며, 다시 제출하라는 안내가 나옵니다. 워크벤치를 거치지 않고 포털에 저장소 주소와 커밋 번호만 직접 입력해 제출하는 경우에는, 그 커밋이 공개 GitHub 저장소에 올라가 있어야 합니다. 비공개 저장소나 내 PC에만 있는 커밋은 원문을 받을 때까지 판정이 보류됩니다.

13~20단계의 공식 판정은 서버의 AI가 그 커밋의 코드를 해당 단계 공식 과제 기준과 대조해 읽고 내립니다. 서버는 학생 코드를 실행하지 않습니다. 따라서 내 PC의 앱 화면에서 보인 결과가 제출 결과를 대신하지 않습니다. 코드 묶음은 압축 기준 3,000,000바이트까지 받으며, 이를 넘으면 과제와 관계없는 큰 파일을 커밋에서 빼라는 안내가 나옵니다. 크기 안에 들어도 심볼릭 링크·하위 모듈·지원하지 않는 경로가 있거나 코드 파일을 UTF-8로 읽을 수 없으면 묶음 전체를 받지 못하고, 판정은 보류됩니다. 이미지나 PDF 같은 파일은 이름과 크기만 확인하므로 그 자체로 오류가 되지는 않습니다. 이런 경우 파일을 지우거나 되돌리지 말고 화면을 강사에게 보여 줍니다. 21·22단계는 제출 기능이 제공되는 경우, 같은 커밋의 학생 문서·실행 코드·설정·잠금 파일을 함께 읽어 일치 여부를 검토합니다. 서버는 학생 코드를 실행하지 않으며, 학생이 적은 재현 기록은 학생의 진술로 구분합니다. 공식 과제 문서에 남아 있는 21·22단계의 native v0.5 자동 확인·실행 설명을 현재 서버가 실행이나 시연 성공을 인증한다는 뜻으로 읽지 않습니다. 공식 제출과 단계 이용 가능 여부는 ALEPH 화면의 현재 안내를 따릅니다.

## 9. 담당자가 SDP 연결 설정을 안내한 경우

SDP 연결 옵션이 포함된 배포본을 받고, 담당자가 본인 프로젝트에 맞는 개인 설정 파일을 안내한 경우에만 사용합니다. 인증서·개인키·토큰과 설정 파일은 학생 프로젝트, on-client 폴더, Git 저장소, 제출 ZIP 밖에 보관합니다. 설정 내용을 채팅이나 도움정보에 붙여 넣지 않습니다.

앱 폴더의 PowerShell에서 아래 명령의 설정 경로를 담당자가 안내한 실제 경로로 바꿔 실행합니다.

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -SdpHostConfig "C:\AlekovPrivate\sdp-host.json"
~~~

이 옵션은 사용자·기기 정보와 업무 앱 접근 판정에 쓰는 SDP 연결을 지정합니다. AI 연결에 쓰는 NativeHostConfig와는 별도 설정입니다. 둘 다 필요한 경우 담당자가 각각의 파일을 안내하며, 한 설정 파일을 다른 용도로 재사용하지 않습니다. SdpHostConfig를 지정하지 않으면 기본 실행 방법을 그대로 사용합니다. 예제 모드(-Demo)와 SDP 연결은 함께 사용하지 않습니다.

서버가 켜졌다는 메시지만으로 SDP 연결이나 업무 앱 접근이 승인된 것은 아닙니다. 실제 사용자·기기 정보와 선택한 앱의 판정 결과를 확인해야 합니다. 연결 오류가 나면 설정·키를 새로 복사하거나 기존 작업을 지우지 말고 담당자에게 도움정보를 전달합니다. 담당자용 설정 계약과 검증 범위는 [SDP_HOST_CONNECTION.md](SDP_HOST_CONNECTION.md)에 있습니다.

## 10. 설치형 전체 앱을 바탕화면 바로가기로 켤 때

마무리 단계에서 `npm run package-app` 한 명령으로 만든 설치형 전체 앱 묶음을 새 폴더에 설치한 경우에만 해당합니다. 바로가기는 앱 폴더의 `tools\start-alekov.ps1`이 아니라 **이 PC의 승인된 실행 host**(`%USERPROFILE%\.aleph-alekov-host\start-installed-normal-app.ps1`)를 그 설치 경로와 함께 실행합니다.

- host는 먼저 앱 출시 정보의 서명을 운영 승인 키로 확인하고, 실행 환경 파일을 모두 확인한 뒤에만 앱을 켭니다. 확인에 실패하면 멈추고, 일반 서버로 바꿔 켜지 않습니다.
- 「운영 앱 승인 키가 아직 없습니다」가 나오면 운영 승인이 아직 배포되지 않은 정상 상태입니다. 설치 폴더는 그대로 두고 담당자의 안내를 기다립니다.
- 「…승인된 앱 출시 정보와 다릅니다」나 「실행 환경 파일이 바뀌었습니다」가 나오면 그 폴더는 그대로 두고 다른 새 경로에 다시 설치합니다.
- 0.2.16용 새 승인 실행 host에서는 SDP 설정 파일이 정말 없는 경우에도 「이 PC 안에서만 쓰는 방식」으로 켜집니다. 보호 현황의 내 PC 상태와 학생 꾸밈을 사용할 수 있고, 로그인·AI 연결·SDP 조회·마무리 연결은 꺼져 있습니다. 연결이 필요하면 담당자가 안내한 정식 설정을 받은 뒤 앱을 다시 실행합니다.
- 설정 파일이 있는데 비었거나 손상됐거나 읽을 권한이 없으면 멈춥니다. 잘못된 파일을 지워서 우회하지 말고 메시지를 담당자에게 보여 주세요. 이전 host에서 「SDP 연결 설정이 없습니다」로 멈췄다면 학생 프로젝트와 설치 폴더를 보존한 채 새 실행 환경 배포 안내를 확인합니다.
- 설치된 폴더 안에서 `tools\start-alekov.ps1`을 직접 실행하면 「바탕화면 바로가기(승인된 실행 host)로만 켭니다」로 멈춥니다. 바로가기를 사용합니다.
- 끌 때는 바로가기 창에서 `Ctrl+C`를 누르거나 창을 닫습니다. 실행과 종료는 내 파일을 바꾸지 않습니다.
- 꾸밈 파일(`student/appearance.json`)과 그 그림을 넣어 포장했다면 설치본도 같은 앱 이름·아이콘·첫 화면 그림·색·카드 배치로 보여야 합니다. 원래 PC 화면과 다르거나 화면 위쪽에 꾸밈 안내가 나오면 설치 폴더는 그대로 두고, 원래 프로젝트의 꾸밈 파일을 확인한 뒤 다시 포장해 다른 새 폴더에 설치합니다. 꾸밈 안내가 나와도 다른 기능은 그대로 씁니다.

### 「내 PC 점검 모드」가 보일 때

설치형 앱이 SDP 설정 없이 켜지면, 새 실행 화면은 위쪽 머리글에 「내 PC 점검 모드」를 표시합니다. 표시가 없다면 실행 모드가 아직 확인되지 않았거나 다른 연결 방식일 수 있습니다. 화면의 현재 상태와 앞의 연결·오류 안내를 확인합니다.

**지금 할 일**

- 위쪽 「내 PC 확인」에서 이 PC의 여섯 항목을 조회합니다. CPU, 메모리, 디스크, 네트워크 구성 요약, Windows 방화벽 세 프로필, 최근 24시간 Windows 기록입니다.
- 자동 조회는 처음에 꺼져 있습니다. 「10초마다 확인」을 직접 체크하면 브라우저의 이 앱 탭이 보이는 동안 10초마다 다시 조회합니다.
- 조회 결과의 확인 시각과 항목별 값·확인하지 못한 항목을 함께 봅니다. 확인하지 못한 항목은 정상이나 안전이 아닙니다.
- 최근 기록의 경고·오류 건수는 관찰한 기록입니다. 이상 징후나 침해 여부는 별도 근거를 확인해야 합니다.
- 이 값은 이 PC를 관찰한 결과입니다. ZTNA 접속 허용, PC 전체의 안전, 침해 사고 없음을 인증하지 않습니다.

이 모드에서 쓸 수 없는 AI 연결·AI 점검 절차는 접혀 있고, 쓸 수 없는 버튼은 눌리지 않게 꺼져 있습니다. 고장이 아닙니다. 학생 화면 확장과 꾸밈, 기존 판정 기록과 원문, 권한은 그대로 남아 있습니다.

**막혔을 때**: 화면에서 모드를 바꾸거나 키를 입력해 연결 기능을 여는 방법은 없습니다. 로그인·SDP·AI가 필요하면 담당자가 안내하는 기존 연결 실행 방법을 따릅니다.

**다른 모드에서는**: SDP 설정이 있는 연결 실행에서는 기존 연결 기능과 실패 안내가 그대로입니다.
